# 国际化验收

已确认：使用 i18next + react-i18next，词典随应用打包。英文 `en` 为兜底；按 `navigator.languages` 优先顺序匹配首个 `en`/`en-*` 或 `zh`/`zh-*`（统一简体中文 `zh-CN`），无匹配/无语言信息使用英文。右上角提供跟随浏览器 / English / 简体中文，仅当前页面生效，刷新恢复跟随；不增加偏好存储、繁体翻译或 URL 语言路由。错误只显示当前语言的友好说明，不显示技术错误码或底层异常。

- I18N-01：语言选择的公开入口覆盖优先级、地区和大小写变体、未知及缺少语言信息。只识别完整基础语言前缀，不把 `zhx` 当中文。
- I18N-02：真实 App 在固定浏览器语言下显示对应名称、输入/输出标签、按钮、placeholder、数量、状态和脱敏错误；`html.lang` 同步，品牌与用户输入不翻译。
- I18N-03：自动模式下浏览器 `languagechange` 重新选择语言，已有输入、缩进、输出和正在运行的任务保留；已发生错误按当前语言重新翻译；卸载移除监听。
- I18N-04：手动选择英中保留输入/配置/输出/运行中 Worker；手动模式忽略浏览器变更，回到跟随立即应用最新浏览器语言；重新挂载恢复自动。失败结果的中英文只显示友好提示，不出现错误码或诊断。
- I18N-E01：en-US/zh-CN/fr-FR 三个独立浏览器 context，375px 下实际格式化、非法 JSON 错误及刷新；无远程词典请求、不横向溢出。
- I18N-E02：真实页面运行后英→中保留输入/配置/结果，再错误后中→英翻译错误。浏览器环境边界通过覆盖 navigator.languages 并触发 languagechange 模拟，Worker 和 JSON 执行均为真实实现。
- I18N-E03：375px 右上角语言选择。E1：默认自动，可聚焦操作；E2：格式化后选择中文保留输入/缩进/结果；E3：浏览器变更不覆盖手动中文，选跟随立即回英文；E4：英文错误后选中文重新翻译，不出现 `INVALID_INPUT`；E5：窄屏不溢出；E6：手动中文后刷新恢复自动英文。映射为 `i18n.spec.ts` 的同 ID 测试，使用 banner 中的 combobox Language / 语言，以及原工具 label / status / alert。

副作用仅限合成文本输入及当前 context 的浏览器语言模拟；不存储、不上传，结束关闭 context。公共规范见 [测试计划](../../docs/testing-plan.md)。
